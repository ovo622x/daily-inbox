# 截图提取提示词

把 `data/snapshots/` 下的截图连同下面这段提示词一起发给任意多模态模型（Claude、GPT、Gemini、本地 Qwen-VL 都行），让它输出 `data/state.json`。

---

## 提示词

```
你会看到若干张桌面端聊天软件的窗口截图，可能来自微信或钉钉。

请从截图中识别出：谁发的、发了什么、什么时候发的、以及有没有需要我去处理的事。

### 输出格式

只输出 JSON，不要解释，结构必须是：

{
  "day": "11月3日 周一",
  "updated": "2026-11-03T20:04:00",
  "sources": {
    "wechat": { "label": "微信", "color": "#07C160" },
    "dingtalk": { "label": "钉钉", "color": "#3296FA" }
  },
  "items": [
    {
      "id": "d1",
      "source": "dingtalk",
      "from": "产品部群",
      "text": "版本评审改到周四 14:00，提前把改动说明发我",
      "action": "写一页改动说明，周四上午前发给对方",
      "kind": "deadline",
      "time": "今天 15:40",
      "deadline": "周四 14:00"
    }
  ],
  "noise": [
    { "id": "w4", "source": "wechat", "from": "家庭群", "text": "[图片]", "time": "17:02" }
  ]
}

### 分类规则（kind）

- overdue：有截止时间且已经过了，但事情还没做完
- deadline：有明确截止时间、还没到期
- reply：对方在等我回话
- todo：要做，但没有截止时间
- info：知道一下就行，不着急

以下一律放进 noise，不要放进 items：
纯表情、单个「ok」「收到」「哈哈」、「牛逼」这类无信息量的回应，
公众号推送、系统通知、加群/扫码入群提示、打卡成功、广告。

### 写 action 的要求

最重要的一条。action 不是复述原文，而是**告诉我下一步具体做什么**。

反例：把「请在今天 12 点前提交」写成「12 点前提交」。
正例：写「12 点已经过了，先问一句还收不收，别直接往群里发」。

反例：「报价单什么时候给？」→「对方问报价单」。
正例：「先回个时间点，哪怕说明天，别让人干等」。

### 其他约定

- id 用 `w1`、`w2`（微信）和 `d1`、`d2`（钉钉），本次内唯一且稳定
- time 用截图里显示的时间原样转写，昨天以前的写日期如 `10-28`
- deadline 没有人话格式就写 null，有就写成 `周四 14:00`、`11月14日 15:00` 这样
- 同一张截图里同一个会话只保留最后一条
- 截图里看不到内容的会话，不要凭标题猜，直接跳过
- 如果某张截图整体是登录二维码或空白，说明这个来源没登录，在 sources 里保留但 items 不加条目
```

---

## 输出之后

把 JSON 存成 `data/state.json`，然后：

```bash
python run.py --build
```

生成的 `site/index.html` 就是最终页面。

> 提示：这一步是整个项目里唯一需要智能的地方。脚本只负责抓图和排版，"什么算一件事""下一步该干嘛"交给模型判断，这也是它能比关键词规则好用得多的原因。
